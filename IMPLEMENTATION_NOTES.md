# Implementation Notes

Last updated: 2026-07-14.

## Implemented

- HTTP MCP endpoint at `/mcp` with Streamable HTTP and JSON responses.
- stdio MCP entrypoint for local clients.
- `validate_newsletter_content` and `preview_draft`.
- HMAC confirmation tokens for `create_draft` and `update_draft`.
- Substack API client scaffolding for auth validation, draft list/get/create/update, and image upload.
- Substack API requests carry an abort signal and use configurable `SUBSTACK_REQUEST_TIMEOUT_MS` timeout handling through the response body read, returning a safe typed timeout error if Substack does not respond or stalls mid-response.
- Draft tools: `list_drafts`, `get_draft`, `create_draft`, `update_draft`, and `upload_image`.
- Auth module with `noauth`, `static_bearer`, and an `oauth` discovery/challenge boundary.
- Runtime config, direct Substack client construction, and Cloud Run planning require `SUBSTACK_PUBLICATION_URL` to be a public `https://` origin before sending cookie-authenticated Substack requests, and normalize copied Substack paths, queries, and fragments to that origin.
- OAuth protected-resource metadata at `/.well-known/oauth-protected-resource`, bearer challenges, JWT/JWKS access-token verification with asymmetric-algorithm allowlisting, and client-visible `_meta.securitySchemes` mirrors for tool descriptors.
- Stateless Streamable HTTP transport with JSON responses, localhost binding by default outside production, Cloud Run-compatible production binding, per-response `X-Request-Id` correlation headers that match structured request logs and HTTP audit log entries, and CORS headers on MCP responses, OAuth metadata, and auth failures, including `mcp-protocol-version`, `last-event-id`, exposed `X-Request-Id`, and exposed `WWW-Authenticate` challenges for browser-style OAuth/static-bearer clients.
- Tool-level scope checks with `_meta["mcp/www_authenticate"]` errors when an authenticated OAuth token lacks the required scope.
- Strict integer parsing for runtime configuration and local/deploy smoke CLIs; malformed partial numeric values such as `123abc` are rejected instead of being truncated.
- Shared client-visible tool descriptor safety statements for read-only, preview, draft write, and image upload tools, with exact draft-only wording on `create_draft` and `update_draft`.
- Confirmation tokens expire at the exact `confirmation_expires_at` timestamp; write tools reject tokens at or after that timestamp.
- Draft title and subtitle metadata are trimmed and whitespace-collapsed at payload construction so confirmation-token title/subtitle normalization is not defeated by the payload content hash; body content is left unchanged.
- Body parsing rejects mixed Markdown/blocks payloads before preview-token generation or write execution, so callers must provide only `body_markdown` for `markdown_v1` or only `blocks` for `blocks_v1`.
- `list_drafts` projects client-returned draft summaries to the documented metadata-only shape before returning them to MCP clients, so raw Substack response fields or draft bodies cannot leak through summary listings.
- `get_draft` omits draft bodies by default and applies `MAX_BODY_BYTES` to requested `include_body` output before returning string or JSON-serializable body content to MCP clients.
- Draft URLs returned by read and write tools are filtered to public `http(s)` URLs without embedded credentials or private-network hosts before reaching MCP clients; unsafe write-result or update-fallback URLs are omitted with a warning.
- `create_draft` does not send an `audience` field unless the caller explicitly provides one, avoiding automatic paid/free audience changes.
- `create_draft` remembers successful `idempotency_key` results in process memory for the preview-token TTL, returning the original draft result for the same generated payload and rejecting same-key/different-payload reuse; this is a duplicate-create guard only and is not durable across restarts, redeployments, or multiple instances.
- `update_draft` sends only caller-provided update fields, omits create-only fields such as `type`, and refuses to update existing posts that Substack does not report as plain unpublished drafts. The fetched item must include a positive draft/unpublished marker such as `status: "draft"`, `status: "unpublished"`, `draft: true`, `is_draft: true`, or `is_published: false`; explicit non-draft `status`, `draft: false`, `is_draft: false`, `is_published`, non-empty `published_at`, or non-empty `post_date` markers still block the update.
- Standalone Markdown `:::image` and `:::latex` directives for explicit agent-generated image metadata and LaTeX blocks.
- Raw HTML is a hard validation error before preview/write-token generation; other unsupported Markdown features remain warning-backed unless strict validation is requested.
- Body-safe audit events for HTTP `create_draft`, `update_draft`, and `upload_image` operations, including safe idempotency-key presence/replay booleans without key values, plus runtime logger redaction for credentials, draft bodies, Markdown bodies, request/raw bodies, idempotency key values, image URLs and payloads, confirmation tokens, optional `MCP_PATH_SECRET` URL segments, and sensitive Error messages/stacks across common snake_case and camelCase field names.
- Client-visible tool errors scrub cookies, bearer tokens, env-style secrets, draft/body content fields, confirmation tokens, and image payload fields; Substack API response excerpts are also capped before they are returned in tool errors.
